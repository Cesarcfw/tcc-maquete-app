# Decisões de arquitetura (ADR)

Registro retrospectivo das escolhas presentes no código 0.6.0, elaborado em 17/10/2026. “Adotado” descreve o estado implementado; não inventa a data original de decisão nem uma aprovação formal do orientador.

1. [ADR-001 — Cliente compartilhado Expo](001-cliente-expo.md)
2. [ADR-002 — Backend local com SQLite](002-backend-sqlite.md)
3. [ADR-003 — Node-RED atrás do backend](003-node-red.md)
4. [ADR-004 — Comando com confirmação](004-confirmacao-comandos.md)
5. [ADR-005 — Programação de luz no serviço](005-programacao-luz.md)
6. [ADR-006 — Preferências sem credenciais](006-preferencias.md)

Para nova decisão: registrar título, status (proposto/adotado/substituído), contexto, decisão, alternativas consideradas, consequências e evidência no código/PR. Alternativas aqui descrevem caminhos possíveis e sua adequação, não um benchmark realizado. Não apagar um ADR quando ele for superado: marcar o substituto e manter o motivo histórico.

Formato inspirado em [Michael Nygard — Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions).
